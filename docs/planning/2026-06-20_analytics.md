# 통계·분석 (기획 방향)

> 작성일: 2026-06-20 · 상태: 기획(미착수). "얼마나 사용하는지, 어느 페이지를 많이 쓰는지" — 운영자(창업자) 관점 제품 사용 분석.

## 0. 누구를 위한 통계인가 (먼저 구분)
- **A. 운영자(창업자) 관점 ← 이번 목표**: 제품이 얼마나·어떻게 쓰이는지. 사업장/사용자 증가, 활성도, 페이지·기능 사용, 무료→유료 전환.
- B. 사장님 관점(인앱): 본인 매장의 출퇴근·급여 추이 등 → 별개 기능(추후).
- → 이 문서는 **A(운영자 제품 분석)** 중심.

## 1. 무엇을 볼 것인가 (지표)
**사용량(Volume)**
- 총/활성 사업장 수(최근 7·30일 출퇴근 발생 기준), 신규 사업장 추이
- 총 직원 수, 활성 직원 수
- **일별 출퇴근 기록 수**(핵심 사용 신호 = attendance)
- 로그인 수(세션/last_login)

**기능 사용**
- SMS·알림톡 발송 건수(notification_logs), GPS 설정 사업장 비율, 명세서 출력·휴가 등록 빈도
- 어떤 기능을 실제로 쓰는지 → 가치 검증

**페이지 사용 ("어느 페이지를 많이")**
- 대시보드/근태/급여/QR/설정/랜딩 등 **페이지뷰** — ⚠️ DB로는 안 보임, 프론트 수집 필요

**사용자 행동**
- DAU/WAU/MAU, 재방문(retention), 이탈 사업장(최근 N일 무사용)

**비즈니스/전환**
- 무료 vs 유료 분포, **전환율(free→paid)**, 문의 건수·유형(inquiry_type), 문의→전환

**퍼널**
- 랜딩 방문 → /create 가입 → 직원 추가 → 출퇴근 사용 → 유료 전환 (각 단계 이탈률)

## 2. 구현 방향 (3안 비교) — 핵심 결정
| 안 | 방식 | 장점 | 한계 |
|---|---|---|---|
| **A. 기존 DB 집계** | attendance·businesses·notification_logs 등 쿼리 → 운영자 콘솔 대시보드 | **추가 수집 없이 즉시**, 데이터 소유, 정확 | 페이지뷰·랜딩 트래픽은 못 봄(서버 액션만) |
| **B. 외부 분석 도구** | 프론트에 스크립트(GA4 / Plausible / PostHog) | 페이지뷰·퍼널·리텐션 자동, 빠른 시작 | 외부 의존, 개인정보·쿠키 동의, (GA4는) 복잡 |
| **C. 자체 이벤트 로깅** | events 테이블 + 프론트 이벤트 전송 → 자체 대시보드 | 완전 통제·맞춤 | 구축·유지 비용 큼 |

## 3. 핵심 인사이트 — 절반은 이미 있다
우리 DB에 **타임스탬프 데이터가 풍부**(attendance.clock_in, notification_logs, inquiries, businesses.created_at/plan, users.last_login_at). → "얼마나 사용하는지"의 대부분은 **추가 수집 없이 쿼리만으로** 답 가능.
- 못 보는 건 딱 하나: **"어느 페이지"(페이지뷰)** = 프론트 수집 필요.

## 4. 권장 설계 (단계적, 하이브리드)
- **P1 (먼저, 빠름): 기존 DB 집계 → 운영자 콘솔 통계 대시보드.**
  - 사업장/직원/활성 수, 일별 출퇴근 추이, 무료/유료 분포·전환, 문의 유형 분포, SMS 발송량.
  - 신규 수집·외부도구 없이 운영자 콘솔(/admin)에 탭 추가.
- **P2: 페이지·행동 분석 = 경량 외부 도구 1개.**
  - **결정(2026-06-20): 쿠키리스(Plausible/Umami) 우선, GA4는 마케팅 본격화 시.**
    - 이유: GA4는 강력하지만 ① 쿠키 동의 배너·개인정보처리방침 부담 ② 급여 다루는 HR 도구를 구글로 추적하는 신뢰 이슈 ③ SPA 수동 추적 세팅. 핵심 제품지표(활성 사업장·전환·출퇴근수)는 어차피 GA가 아닌 우리 DB(P1)에서 나옴.
    - **쿠키리스(Plausible/Umami)**: 동의 배너 불필요, 가볍고 "어느 페이지·유입" 충분. 국내 SMB·HR 신뢰 프로필에 적합. (트레이드오프: 깊은 세그먼트·퍼널은 약함)
    - **GA4 채택 조건**: 광고 본격 집행 + Google Ads 연동 + 상세 퍼널 필요 + 쿠키 동의 감수 시.
  - PostHog(제품분석·퍼널·세션, 셀프호스팅)도 대안.
- **P3(선택): 자체 이벤트 로깅** — 특정 행동(업그레이드 클릭, 명세서 출력 등) 정밀 추적 필요 시.

## 5. 개인정보·정책
- 사용 분석은 개인정보처리방침에 **분석 목적** 명시 필요.
- GA4 등 쿠키 기반은 **쿠키 동의** 배너 필요(국내 규제·UX 부담). **쿠키리스(Plausible/Umami)면 동의 부담↓**.
- 운영자 콘솔 집계(P1)는 우리 데이터 내부 집계라 부담 적음(이미 보유 데이터).

## 7. 권장 시작점
**P1: 운영자 콘솔 통계 탭** — 이미 있는 데이터로 "사업장 수·활성도·일별 출퇴근·유료 전환·문의 유형"을 보여주는 대시보드. 외부 도구·동의·신규 수집 없이 바로 가치. "어느 페이지"는 P2에서 경량 도구로.
